# 相容性與測試範圍

本工具檢查實際環境能力，不以機型名稱決定是否允許修復。「自適應」指自動選擇符合條件的 Windows、EFI 和可用韌體操作，並不是自動取得所有電腦的驅動。

| 項目 | 條件／範圍 |
| --- | --- |
| 執行環境 | 原生 ARM64 Windows PE、UEFI；已安裝 Windows 或 x64 模擬程序不允許修復。 |
| PE 執行階段 | PowerShell 5.1、.NET Framework 子集、WMI／StorageWMI、SHA-256／CSV／純文字功能。 |
| 目標 Windows | 可讀取且檔案完整的 ARM64 安裝；kernel、winload、boot manager 架構皆需符合。 |
| 磁碟 | 線上、可寫入的 GPT；受支援的內建型匯流排，例如 NVMe、UFS、SATA。 |
| EFI | 與 Windows 在同一實體磁碟，FAT32、ESP 類型，空間足夠；不建立分區。 |
| 分區識別 | 複製後重複的 GPT 識別碼需要先處理，避免韌體選錯碟。 |
| 備份 | 另一個實體 USB／SD 媒體，足夠容納完整 EFI 備份及日誌。 |
| 韌體 | 標準 UEFI Boot 變數；512／4096 位元組邏輯磁區，64 MiB 至 4 GiB ESP。OEM 限制可能阻擋存取。 |
| BitLocker | 需事先由使用者解鎖；工具不索取、不儲存或繞過復原金鑰。 |
| 多重開機 | 選中的 Windows 設為預設；保留其他 EFI 目錄和無關韌體項，建議互動模式。 |

匯流排資訊無法絕對區分內建 NVMe 與某些 Thunderbolt 外接盒；使用前拔除無關外接儲存裝置，只保留修復／備份媒體。互動畫面會顯示目標磁碟，供使用者核對。

不涵蓋 BIOS/MBR、x86/x64 Windows、USB Windows To Go、虛擬硬碟開機、跨磁碟共用 ESP、建立／調整分區、Windows 檔案修復、OEM 恢復流程、驅動部署或 Secure Boot 金鑰管理。

原始工具曾用於 HP ARM 筆電遷移情境；其結果促成 CSV 日誌和直接 UEFI 變數修復設計。**這些歷史紀錄不是此通用版本的實機測試結果。v0.1.0 的完整實機開機測試仍待完成。**

## 自動化驗證

- C# 模擬韌體測試：UEFI 載入項編碼、512／4096 磁區、重複執行、既有項保留、每一步失敗、讀回異常、並行變更、回復失敗。
- PowerShell 測試：候選篩選、架構、歧義、備份位置、韌體策略、暫存掛載和報告等執行邏輯。
- 安裝／封裝測試：離線路徑、啟動整合、重複安裝和檔案完整性。
- GitHub Actions 在 Windows 上建置與執行模擬測試，不寫入 runner 的開機分區或真實 UEFI 變數。

v0.1.0 本機驗證：77 項 C# 韌體模擬、170 項 PowerShell 執行流程、32 項封裝／安裝檢查，共 279 項通過。

通過這些測試表示對應的程式行為符合斷言。韌體寫入成功並讀回一致，也不能證明 Windows 驅動和系統本身能正常開機。斷電時無法承諾交易原子性；修復期間保持穩定供電。
